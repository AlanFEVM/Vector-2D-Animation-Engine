# 原生扩展与主线功能计划

## 定位

扩展是引擎原生功能的专题入口，不是第三方插件运行环境。MC 扩展集中提供创作者需要的场景、素材与特效操作；能够独立服务普通动画创作的能力，应当出现在常规工具、素材库或舞台菜单里，不要求用户先打开 MC 扩展。

## 实施顺序

容量更新：剖面 JSON 的读取上限调整为 256 MiB、100 万个输入方块；可见内容仍保留 20000 个方块、128 个深度图层的限制。下方首版数值为初始规划。

1. **原生入口**：顶栏增加「扩展」。引擎自己的代码通过内部命令接入点添加扩展操作；未接入时显示明确的空状态。本阶段不读扩展文件，也不修改工程格式或加载外部程序。
2. **定义首个描述文件**：`.v2dextension` 是声明式 JSON；版本 `1` 要求 `formatVersion: 1`、`id: "minecraft-scene"`、`workflow: "minecraft-scene"`。该文件仅启用引擎已编译的对应工作流，不加载脚本、程序集或其他外部程序。随原生构建复制到应用目录；移除后重启即可拆下，也可用 `-p:IncludeMinecraftSceneExtension=false` 构建不含该模块的版本。
3. **MC 试点**：首版可从 Ortho Camera 剖面生成新的原生 2D 场景，保留可编辑图层与工程贴图。贴图目录是平铺 PNG 目录；可选映射接受简名或带命名空间的键，以及贴图名称字符串或包含 `side` 的对象。首版最多处理 100000 个输入方块、20000 个可见方块、128 个深度图层；缺失贴图时只检查不写入。实时预览与应用留待后续，且只能更新扩展管理的场景内容。粒子预设、MC 数据与九格物品栏仍留在专题工作流。

## 主线候选

| 优先级 | 功能 | 用户操作与边界 |
| --- | --- | --- |
| 先做 | 素材铺绘 | 从素材库选择图片，沿固定网格拖动落印；晚些可加框选区域铺满。每格可修整，整笔可撤销。复用已有方形笔尖、吸附和像素采样能力中适用的部分，不重复造相关设置。 |
| 随试点验证 | 替换选中的素材 | 从库中挑新素材，只替换舞台上选中的摆放，保留位置和动画，不影响共用旧素材的其他对象。与现有「从源文件更新／替换源文件」区分。若创作者都在游戏内修改并同步，不强行推进。 |
| 粒子阶段优先 | 从图片创建循环动画 | 把图片序列或规则分格的长图生成能拖上舞台、由时间轴预览的动画元件。火、水、眨眼、闪光等无需粒子系统。 |
| 待实际需求 | 碎片飞散 | 先检验现有「随机破碎」能否满足需求。若缺的只是位图或元件也能做碎屑，优先评估扩展已有命令，不新增重复入口。 |

已有图层和视差就是分层背景，不新增同义对象。试点以朋友下一段真实镜头为验收：导入、补景、走镜头、加入循环素材、保存重开；记录哪一步仍需回 Animate，以及下一个类似镜头他是否愿意在引擎里继续做。
