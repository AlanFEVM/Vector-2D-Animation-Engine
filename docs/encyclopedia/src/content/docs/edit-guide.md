要修改当前词条，在页面顶部选择“普通编辑”或“源码编辑”。两种模式共享一份正文，可在保存前切换到“预览”。

## 开始编辑

普通编辑直接修改排版后的文字。选中文字可加粗、设为斜体；将光标放在段落内可把它改为二级标题。源码编辑使用 Markdown：章节使用 `##` 和 `###` 标题，链接使用 `[文字](地址)`，图片使用 `![说明](路径)`。含表格等扩展语法的段落请用源码模式，以保留原始格式。

点击“保存”后，本机百科服务会写入该词条的 Markdown 文件、重建页面并刷新。点击“取消”可放弃草稿。如果另一个标签页已经保存了同一词条，当前草稿会保留在编辑框里，保存不会覆盖对方的修改。标题、导航和首页工作台图片不属于可编辑正文。

## 编写词条

新建机制词条时，建议从[词条模板](/entry-template/)开始，并按下面的顺序组织内容：

1. **概念**：说明这个功能或机制解决什么问题。
2. **规则**：说明触发条件、处理顺序、数据关系和用户能观察到的结果。
3. **边界情况**：记录不支持的组合、版本差异、限制和容易误解的行为。
4. **相关词条**：链接到依赖它或与它一起使用的功能。

描述应以当前源码和实际软件行为为准。不要把计划中的功能、实验性实现或猜测写成已经完成的能力；如果行为尚未稳定，请明确标注当前阶段。

## 页面标准

页面标题使用功能的正式名称。第一次出现的专有名词可以同时写出英文标识，例如“自动关键帧（Auto Key）”。同一页面内保持术语一致，不要在“元件”“符号”“实例”等词之间随意切换。

每个章节只解决一个问题。较长的说明拆成多个小节，操作步骤使用有序列表，参数和快捷键使用表格或代码格式。描述界面操作时，给出菜单、按钮或工作区的准确名称，并说明它受哪些上下文条件限制。

## 添加图片

图片用于说明真实界面、操作结果或数据关系。截图应裁剪到相关区域，保留足够的上下文，并使用准确的替代文字。图片文件放在百科项目的 `public/` 或内容附近的资源目录中，文件名使用简短的英文或拼音，避免空格和无法识别的版本信息。

不要上传与当前功能无关的装饰图，也不要使用未经许可的第三方素材。需要展示编辑器状态时，优先使用项目已有截图或重新截取当前版本的界面。

## 建立链接

优先链接到百科内已有词条、用户手册和源码中稳定的相关说明。链接文字应表达目标页面的内容，不要大量使用“点击这里”这类没有上下文的文字。

如果目标页面尚未建立，可以先链接到[词条模板](/entry-template/)，或在 Pull Request 中同时创建目标页面。不要留下指向不存在页面的链接。

## 提交前检查

提交前请检查以下内容：

- 说明是否与当前软件行为一致，是否区分已实现、实验性和计划中的能力。
- 页面标题、章节层级、术语和快捷键格式是否统一。
- 图片是否能正常加载，替代文字是否能说明图片内容。
- 页面内链接是否有效，中文标点和代码格式是否正确。
- 是否只修改了与本次词条有关的文件。

先使用本地预览检查页面，再提交修改。构建命令见百科目录中的 `README.md`；如果修改涉及编辑器本身的行为，还需要同时更新[用户指南](https://github.com/AlanFEVM/Vector-2D-Animation-Engine/blob/master/docs/USER_GUIDE.md)。

## 其他问题

如果不确定某个机制的实际行为，可以在社区讨论，或在问题描述中附上版本、工程状态和复现步骤。QQ群号和事务群链接将在社区信息补充后更新。
